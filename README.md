# Sonora Web — prototype

Responsive browser music player prototype.

## Run
Open `index.html` in a modern browser (Chrome, Edge, Firefox, Safari). For best results use a local static server:
- `python -m http.server 8000`
- open http://localhost:8000

## Included
- Responsive desktop/mobile UI
- Import audio files into browser IndexedDB
- Playback, seek, volume, next/previous, shuffle, repeat
- Search and delete tracks from the local library
- 10-band Web Audio equalizer and bass/audio presets

## Important storage note
This prototype stores uploaded audio in the current browser profile on the current device. It is not cloud storage and does not sync across devices. Browser storage can be cleared by the user/browser and may have quota limits.

For the production cloud version, add:
1. User authentication.
2. A private S3-compatible bucket (e.g. Evolution Object Storage or Yandex Object Storage).
3. A small backend/serverless API that issues short-lived signed upload/download URLs.
4. A database table for track metadata and ownership.
5. Delete endpoint that removes both the object and its metadata.

Never put S3 access keys in frontend JavaScript. Check current provider pricing, free-tier eligibility, egress charges, and access from target regions before launch.


## PIN screen
The prototype now shows a six-digit numeric PIN screen. The PIN is checked in the browser using a SHA-256 digest, and the unlocked state lasts for the current browser tab session.

**Security limitation:** GitHub Pages is static hosting. The HTML/JavaScript is public and can be inspected or bypassed, so this PIN is only a casual privacy barrier for a small trusted group—not real access control. Anyone with the site URL and basic technical knowledge can bypass it. Do not store confidential or sensitive files behind this gate.

For actual restricted access while keeping GitHub Pages, put an access-control proxy in front of the site (for example, Cloudflare Access) or use a backend that validates the PIN and issues a secure session. Do not rely on a frontend-only PIN for private cloud audio.

## Selected deployment architecture
- Frontend: GitHub Pages (static files).
- Audio objects: Evolution Object Storage (private bucket).
- Browser uploads/downloads: short-lived pre-signed URLs generated by a trusted backend/API.
- Metadata: a small database/API can track object keys, titles, sizes and durations.
- Deletion: backend validates the request and deletes the matching object from the bucket.

**Never place Evolution S3 access keys in `index.html` or any frontend JavaScript.** A static GitHub Pages site cannot safely generate S3 signatures using a permanent secret. The cloud-storage connection is not yet wired into this prototype; the current upload library remains local to the browser.

## Publish on GitHub Pages
1. Create a GitHub repository, e.g. `sonora-web`.
2. Upload `index.html` (and this README if desired) to the repository root.
3. In repository Settings → Pages, choose deployment from the `main` branch and `/ (root)`.
4. Wait for GitHub Pages to publish the site; open the generated `github.io` address.
5. For cloud storage, configure a private Evolution bucket and add a backend for pre-signed upload/download URLs before enabling cloud uploads.

Check Evolution Object Storage's current pricing, free allowance, traffic/egress fees and S3-compatible API details before launch; free quotas and offers can change.
